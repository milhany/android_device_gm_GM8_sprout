# GM8 3.18 memory-management compatibility candidate

Experimental branch: `lineage-19.1-lmkd-test` in all three GM8 repositories.
Device base: 59f8af9a02c5a1c7832273ac6d1bf2a4e2de7092.
Paired kernel: 496ace2d356d154ec0ff6ea6d8bb91ce8b8ece20.
Paired vendor: 74d9accadb684a30bae2339c6a97bf5feb87028e.

## Purpose and limits

The current 3.18 kernel has HMP and the old Qualcomm in-kernel LMK, no PSI,
and previously disabled memcg. Android 12.1 LMKD uses the kernel LMK if its
minfree node exists. Merely enabling memcg would not change that selection.

This candidate enables the existing memcg v1/eventfd implementation and swap
accounting, removes the old kernel LMK, and requires a memory mount at
/dev/memcg. LMKD explicitly uses its existing vmpressure strategy and the
framework-provided minfree thresholds. It does not gain PSI/thrashing-based
decisions. No 4.19, pidfd or scheduler backport is included. The audited AOSP
LMKD has a no-pidfd fallback on older kernels.

Per-app memcg stays off. /acct process tracking and the nine CPU-root task
profiles remain unchanged. LowMemoryUsage/HighMemoryUsage override their
default memory attribute actions with empty action lists so they cannot
accidentally place app limits on a shared root/system group; the default
swappiness=150 is also unsupported by this 3.18 memory controller. Android's
SystemMemoryProcess profile remains available. The obsolete vendor-init
/sys/fs/cgroup/memory/bg path and swappiness=140 write are removed.

The paired vendor bypasses missing KLMK/ALMK nodes on SoC 313, explicitly
keeps PPR off, and retains the preceding 1.5 GiB zRAM, compression, swappiness,
readahead, CPU and thermal policies. The ART heap and 100 MiB ODEX/VDEX
prefetch baseline are unchanged. Keep the stock-heap and 16 MiB ART-prefetch
experiments separate; the source gate rejects the known mixed settings.

This tests a different memory-pressure/kill path, not a demonstrated cure for
all stalls. Memcg costs additional metadata and accounting work. Lower empty
RAM is not a success/failure criterion; compare switch stalls, app reloads,
launch times, kills and sustained responsiveness. The LMKD minfree mode still
closes eligible apps under pressure. Kernel OOM handling remains available.

## Build on the existing host/container

First preserve any local source edits. From ilhan@ubuntu (host), or builder
inside gm8-build:

```sh
cd ~/android/lineage-19.1 &&
git -C device/gm/GM8_sprout fetch --no-tags https://github.com/milhany/android_device_gm_GM8_sprout.git lineage-19.1-lmkd-test &&
git -C device/gm/GM8_sprout switch --detach FETCH_HEAD &&
bash device/gm/GM8_sprout/tools/build-lmkd-test-19.1.sh
```

The entry point enters the existing Docker container on the host, pins the
kernel/vendor commits, refuses tracked local edits, holds the existing build lock while selecting
sources, records previous source
revisions and calls the existing kernel-output-cleaning, user/release-key
target-files workflow. No source reset, auto-flash or data wipe is performed.
Generated KERNEL_OBJ/.config is checked after the build and before signing;
it is also saved with the build records. Old release outputs remain available.

If a preceding ART-prefetch trial was applied, restore it with that trial's
apply-art-prefetch-compat.py --restore before selecting this branch. Do not
reset unrelated build/make edits to get past the guard. This branch requires
unmodified AOSP android-12.1.0_r22 lmkd.cpp; a different source needs review.

Successful outputs retain the existing paths:

```
~/android/gm8-release/latest/gm8-19.1-user-release.zip
~/android/gm8-release/latest/gm8-19.1-user-release-boot.img
~/android/gm8-release/latest/build.log
```

The phone currently runs stock Pie. Do not dirty-flash this over stock or
install only boot.img. Back up user data and plan a clean Lineage installation
with the matching recovery and complete signed package. The signing helper's
update-mode label means existing GM8 Lineage keys were reused; it does not
verify the installed phone or make stock-to-Lineage data migration safe.
No installation has been performed or authorized by running this build script.

## Validation completed here

- Actual kernel Kconfig generation: MEMCG/MEMCG_SWAP/MEMCG_SWAP_ENABLED,
  SWAP and EVENTFD built in; MEMCG_KMEM and kernel LMK disabled.
- Cross-compilation of the whole mm/ built-in object, kernel/cgroup.o,
  kernel/res_counter.o, kernel/fork.o and fs/proc/base.o with AOSP GCC 4.9.
  See the kernel branch's Documentation/gm8-lmkd-test.md for toolchain/host flags.
- Actual vendor-function fixtures: six no-KLMK cases, legacy GM8/other SoCs,
  actual zRAM sizing and substituted swap-command order all pass.
- Candidate source/generated-config checks pass. Seven incompatible or
  missing kernel/property/mount/profile/vendor cases are rejected by tests.
- Actual Android task-profile override/dispatch functions confirm that empty
  memory profiles remove inherited attribute writes and succeed. Existing RT
  admission/root-path and aggregate cpuset/IO/slack regression checks pass.
- Release-wrapper fixtures confirm source selection holds the build lock,
  selection failures stop before output cleanup/signing, and previous releases
  and source/key files remain preserved.
- Python compilation, shell entry-point syntax and diff whitespace checks.

This is not a full linked kernel, Android target-files build, SELinux/runtime
integration test, boot test or performance result. The build host must still
pass full preflight, m nothing and target-files/signing checks. Do not bypass
neverallows or permissions to start LMKD. A memcg mount/permission failure can
prevent this critical service from starting; stop and roll back if that occurs.

## Hardware acceptance after a separately planned installation

Immediately after boot, use ordinary unrooted ADB:

```bat
adb shell getprop ro.lmk.use_psi
adb shell getprop ro.lmk.use_minfree_levels
adb shell getprop ro.config.per_app_memcg
adb shell device_config list lmkd_native
adb logcat -b all -d | findstr /I /C:"Using vmpressure" /C:"Using in-kernel low memory killer" /C:"Kernel does not support memory pressure" /C:"lmkd"
```

Expected properties: false, true, false; the startup log must say
"Using vmpressure for memory pressure detection", without repeated service
deaths. DeviceConfig overrides can take precedence over ro.lmk values, so
read-only property output alone is insufficient. If boot logs have already
rolled out, their absence proves nothing. Do not assume /dev/memcg or
/proc/swaps is readable from a user-build shell or broaden permissions.

Then compare a fixed app-switch sequence (same app versions/content, no force
stops or manual compilation during the run), both early after boot and after
normal use. Record reloads and long pauses as well as launch times. Check
camera, cellular, display, suspend and thermal behavior before daily use.
Investigate battery only with matched charging/radio/music conditions.

Rollback: keep the stock recovery/ROM path and backups. To rebuild the prior
Lineage candidate, restore device 59f8af9, vendor 84fc751 and kernel 44e0901,
then build/sign the complete package with the same existing keys. A source
rollback does not restore phone data or resolve cross-ROM encryption changes.
